# ADR-040: Documentary truth and baseline of the tool contract

Status: Accepted. Point 3 of the decision and row D-H1 are superseded by [`docs/adr/ADR-050.md`](ADR-050.md): the package is published on PyPI, on npm and as a git tag.

## Context

The server's documentation and its code say different things.

| The documentation said | The code does |
|---|---|
| `search_by_metadata` (`tag` filter), `search_deep` and `compare_flows` are broken | All three work (commits `9bd99ff` for the `tag` filter, `506bc20` for `search_deep` and `compare_flows`, with tests in `ccae767`); verified live on cloudfrog-knowledge (`:8200`), where `compare_flows` only exercised the error path |
| Four subpackages `indexer/graph/usage/tools` | 13 flat modules in `src/knowledge`; `.importlinter` contracts five module levels |
| `schema/frontmatter.yml` validates every document | There is no `schema/`; the indexer reads the frontmatter and does not validate it |
| Real Chroma via Testcontainers | There is no Testcontainers dependency; the suite uses a real `PersistentClient` in a temporary directory and a deterministic embeddings double in `tests/conftest.py` |
| `uv run mypy src/knowledge` as a verified command | `mypy` is in the `dev` group, but no workflow runs it |
| The server never writes outside `90 - Memory/` | `sync_confluence(dry_run=False)` writes under `Conventions/**` |
| `reindex` suggests exporting to Bitbucket Downloads | `export_hint` is hard-coded in `server.py` and the real remote is GitHub |

The `repair-mcp-tool` skill and the two `CLAUDE.md` files (root and `ops/contexts/cd-knowledge-mcp/`) inherited those claims.

## Decision

1. The three tools documented as broken work. They are not repaired: the documentation is corrected.
2. The current behavior of the 14 tools is the contract baseline (golden master). Every change of response shape starts from there and is versioned.
3. The distribution is called `cloudfrog-knowledge`, is private and is consumed through `git+ssh` pinned to an immutable tag; it is not published on PyPI.
4. The vault is a directory. The server only knows `path`; whether the directory lives in a git repo (with a deploy key and a webhook) is optional and specific to the hosting.
5. Vault repos are one per organization, in the organization that owns the content when there is one.

Summary of the decisions that support the above (numbering of the decoupling plan; F4, F9 and G4 have no statement of their own and are not summarized):

| Id | Decision | Rationale |
|---|---|---|
| D-H1 | Private `knowledge` repo, no PyPI, distribution through `git+ssh` to a tag | Owner's decision; Claude Code clones with the machine's credentials |
| D-H2 | Cloud frog and Initech accept egress to OpenAI and TypeSafe | Removes data egress as an argument against embeddings and rerank |
| D-H3 | `knowledge` and `memory` stay in the owner's personal account; the vaults live in the organizations | Without a transfer, `go.mod`, GHCR, npm and Dokploy do not change |
| D-H4 | `vault-initech` is born empty and receives the history of `Work/Initech/` | Preserves a real PR review |
| D-H5 | Two organization vaults and two in the personal account; own template | Avoids mixing a foreign organization with the personal account |
| D-H6 | Conventions are split by the frontmatter `scope` | The frontmatter rules over the folder; without the global copy, wikilinks break |
| D-H7 | Upstream PRs to `memory` are accepted | The plugin rename can only live in `memory` |
| D-H8 | All consumers of the contract are our own | The `search_code` removal window is one release |
| D-H9 | Actions disabled at the start; gates run locally; the pipeline port comes in with `workflow_dispatch` | Slowness and cost; seeing green on Linux is the last gate. In `knowledge`, D-H9 is closed by F11: ring1 runs on every pull request and push to `main`, and stale-report every week (`README.md`, "Tests and merge gates (ring 1)") |
| F1 | No repo changes owner | Avoids rewriting modules, images and deployments |
| F2 | Vault in the organization that owns the content; Initech and personal in the owner's personal account | The content owner is the one who reviews |
| F3 | Marketplace, releases and tap public in `cloudfroghq`, without source code | Fixes the Homebrew installation without exposing code |
| F5 | Consumers confirmed as our own | Closes the consumer survey |
| F6 | AcmeDrive accepts egress to TypeSafe | `rerank: jev` declared in the four vaults |
| F7 | AcmeDrive's content comes out of the `:8100` container; its Bitbucket repo is abandoned | That content does not exist in this repo |
| F8 | Organizations on the Free plan: D-11 by convention (CODEOWNERS, lint in CI, PR only) | There is no effective branch protection in private repos on the Free plan |
| F10 | Content migration without `.obsidian` binaries or duplicates | No review value |
| F11 | Reactivating Actions and seeing green on Linux is the last gate | macOS already hid a case-sensitivity defect |
| G1 | The vault is a directory, independent of git | A volume or synced folder must not need git for `reindex` |
| G2 | Initech and AcmeDrive do not get access to the code repos | They consume the deployed server, not the code |
| G3 | Marketplace, binaries and tap public; other teams use only the remote plugin | A channel with no per-person credentials |

## Consequences

- `CLAUDE.md`, `ops/contexts/cd-knowledge-mcp/CLAUDE.md` and `README.md` describe the server, the packaging and the deployments as they are; the `repair-mcp-tool` skill applies to any tool documented as broken with its regression test in red, and today none is.
- An index built before `9bd99ff` needs `reindex(force=true)` once for the `tag` filter to return results.
- The following enter contract 1.1, declared as explicit changes over the baseline:
  - the order of the results of `find_path`, `get_related` and `get_impact` depends on `PYTHONHASHSEED` and is not contract in the baseline (the golden records it with the seed at 0 and only compares these three as a set under another seed); contract 1.1 orders it deterministically and then the golden freezes it;
  - `reindex` omits `export_hint` when the vault does not declare `repo`, and adds `vault_sync` (`pulled`, `skipped_no_repo` or `failed`) so that a vault without git does not look like a silent failure.
- No tool changes shape or parameters in this ADR.
