# ADR-040: Verdad documental y línea base del contrato de tools

Estado: aceptado.

## Contexto

La documentación del servidor y el código dicen cosas distintas.

| La documentación decía | El código hace |
|---|---|
| `search_by_metadata` (filtro `tag`), `search_deep` y `compare_flows` están rotas | Las tres funcionan (commits `9bd99ff` para el filtro `tag`, `506bc20` para `search_deep` y `compare_flows`, con tests en `ccae767`); verificadas en vivo en cloudfrog-knowledge (`:8200`), donde `compare_flows` solo mostró el camino de error |
| Cuatro subpaquetes `indexer/graph/usage/tools` | 13 módulos planos en `src/knowledge`; `.importlinter` contrata cinco niveles de módulos |
| `schema/frontmatter.yml` valida todo documento | No existe `schema/`; el indexador lee el frontmatter y no lo valida |
| Chroma real vía Testcontainers | No hay dependencia de Testcontainers; la suite usa un `PersistentClient` real en un directorio temporal y un doble determinista de embeddings en `tests/conftest.py` |
| `uv run mypy src/knowledge` como comando verificado | `mypy` está en el grupo `dev`, pero ningún workflow lo ejecuta |
| El servidor nunca escribe fuera de `90 - Memory/` | `sync_confluence(dry_run=False)` escribe bajo `Conventions/**` |
| `reindex` sugiere exportar a Bitbucket Downloads | `export_hint` está fijo en `server.py` y el remoto real es GitHub |

La skill `repair-mcp-tool` y los dos `CLAUDE.md` (raíz y `ops/contexts/cd-knowledge-mcp/`) heredaban esas afirmaciones.

## Decisión

1. Las tres tools documentadas como rotas funcionan. No se reparan: se corrige la documentación.
2. El comportamiento actual de las 14 tools es la línea base del contrato (golden master). Todo cambio de forma de respuesta parte de ahí y se versiona.
3. La distribución se llama `cloudfrog-knowledge`, es privada y se consume por `git+ssh` pineada a un tag inmutable; no se publica en PyPI.
4. El vault es un directorio. El servidor solo conoce `path`; que el directorio viva en un repo git (con deploy key y webhook) es opcional y propio del hospedaje.
5. Los repos vault son uno por organización, en la organización dueña del contenido cuando existe.

## Evidencia

Llamadas en vivo contra `cloudfrog-knowledge` (HTTP, puerto 8200, vault `vault/cloudfrog`), bearer de alcance de usuario.

`reindex(target="vault", force=true)`:

```json
{"files":151,"new":116,"updated":32,"unchanged":0,"chunks":886,"export_hint":"Run scripts/export-data.sh to upload index to Bitbucket Downloads"}
```

Observaciones: `new + updated + unchanged = 148` frente a `files = 151` (tres archivos sin clasificar); `export_hint` apunta a Bitbucket Downloads.

`search_by_metadata(tag="type/runbook")` devuelve tres resultados; `file_path` sale sin prefijo y sin corchetes de wikilink:

```json
{"result":[
 {"file_path":"Projects/Example API/Runbooks/Database Migrations.md","type":"runbook","status":"complete","tags":["type/runbook","service/example-api","runbook/database"]},
 {"file_path":"Projects/Example API/Runbooks/Setup Local.md","type":"runbook","status":"complete","tags":["type/runbook","service/example-api","runbook/setup"]},
 {"file_path":"Projects/Example API/Runbooks/Troubleshooting.md","type":"runbook","status":"complete","tags":["type/runbook","service/example-api","runbook/troubleshooting"]}]}
```

Las rutas y etiquetas de arriba están neutralizadas; la forma de cada fila es la que devolvió el servidor.

`search_deep(query="middleware outage", depth=1)` devuelve cinco resultados; la corrutina se espera sin `coroutine is not iterable`. Una fila con `discovered_via: "direct"` y cuatro con `discovered_via: "hop:<nota de partida> -> outgoing"`, con `score` entre 0,35 y 0,53; rutas y extractos neutralizados:

`compare_flows(provider1="Hub", provider2="OAuth")` devuelve el error estructurado documentado, sin traza de Python, bearer ni clave; el vault de Cloud frog no tiene flujos y la comparación real corresponde al vault de AcmeDrive:

```json
{"error":"Provider 1: No flow file found for provider 'Hub'."}
```

Conclusión: las tres tools documentadas como rotas responden en producción tras `reindex(force=true)`.

## Consecuencias

- `CLAUDE.md`, `ops/contexts/cd-knowledge-mcp/CLAUDE.md` y `README.md` describen el servidor, el empaquetado y los despliegues como son; la skill `repair-mcp-tool` aplica a cualquier tool documentada como rota con su test de regresión en rojo, y hoy ninguna lo está.
- Un índice construido antes de `9bd99ff` necesita `reindex(force=true)` una vez para que el filtro `tag` devuelva resultados.
- Entran en el contrato 1.1, declarados como cambios explícitos sobre la línea base:
  - el orden de los resultados de `find_path`, `get_related` y `get_impact` depende de `PYTHONHASHSEED` y no es contrato en la línea base (el golden lo graba con la semilla en 0 y solo compara estas tres como conjunto bajo otra semilla); el contrato 1.1 lo ordena de forma determinista y entonces el golden lo congela;
  - `reindex` omite `export_hint` cuando el vault no declara `repo`, y añade `vault_sync` (`pulled`, `skipped_no_repo` o `failed`) para que un vault sin git no parezca un fallo silencioso.
- Ninguna tool cambia de forma ni de parámetros en este ADR.
