# ADR-044: The vault write fence enters contract 1.3.0

Status: Accepted. Replaces the row "`sync_confluence(dry_run=False)` → `E_WRITE_FENCED`" of the deferred-points table in ADR-042, which carried it to 2.0: the fence enters in 1.3.0. The rest of ADR-042 does not change.

## Context

ADR-040 recorded the contradiction between "the server never writes outside `90 - Memory/`" and what the code did: `sync_confluence(dry_run=False)` rewrote in place the `Conventions/**` files that carry `confluence_id`. That write is the only path in the server that changes curated content without a human PR, and rule D-11 says the vault is edited only by PR with the owner as reviewer.

ADR-042 deferred the fence to 2.0 because it changes the behavior of an existing parameter. Three facts moved that decision:

1. The only consumer of the write path was `scripts/sync.sh` (and its twin `scripts/sync.py`), which called `confluence_sync.sync(dry_run=False)` directly, without going through the tool. A fence in the tool alone did not stop them.
2. The two AcmeDrive `launchd` agents that triggered that script are disabled (`*.plist.disabled`).
3. No context package in `ops/contexts/` uses `dry_run=False` (`rg -n 'dry_run=False' ops/` finds only prose in `CLAUDE.md`, no call).

## Decision

1. **The fence lives in `confluence_sync.sync()`**, not only in the tool. With `dry_run` other than `True` it raises `KnowledgeToolError` with `E_WRITE_FENCED` and a message pointing to `cloudfrog-knowledge confluence export`, without reading credentials or files. The function has no write path: `updated` stays in the report, always empty.
2. **The `sync_confluence` tool responds `isError` with `E_WRITE_FENCED`** to `dry_run=False`, whatever `vault` is named (the 1.1.0 `E_ARGUMENT_CONFLICT` for another vault disappears: there is no write left to limit to the default vault). The response is deterministic and is recorded in `tests/golden/v1.3.0/sync_confluence__fenced.json`. With `dry_run=True`, the response is that of 1.2.0 byte for byte. The parameters, their order and the `outputSchema` do not change; the catalog description says it is read-only.
3. **`cloudfrog-knowledge confluence export` is born**: it writes the pages newer than their vault file under an output directory (by default `<data_dir>/<slug>/confluence-export/`) with the vault's frontmatter and `last_updated` set to the day the page changed. It rejects with `E_WRITE_FENCED` an `--out` inside any served vault, and re-checks each file, already resolved, right when writing it, so a symlink into the vault does not get through either. Promotion is a human PR ([`docs/runbooks/promote-confluence.md`](../runbooks/promote-confluence.md)).
4. **Credentials come from the vault manifest**: `integrations.confluence.site` and `integrations.confluence.secrets.{email_env,token_env}` name the site and the variables; whatever `integrations.confluence` does not declare comes from `CONFLUENCE_URL`, `CONFLUENCE_EMAIL` and `CONFLUENCE_TOKEN`, so a deployment that defines only those three variables stays the same.
5. **`scripts/sync.sh` and `scripts/sync.py` are removed**, together with their mentions in `README.md` and `scripts/README.md`.
6. **The vault volume becomes read-only** in `infra/compose.org.yml`: no server writer needs it writable, and `90 - Memory/` has its own volume.

## Consequences

- `docs/contract/CHANGELOG.md` 1.3.0 declares in "Changed (non-additive)" `sync_confluence(dry_run=False)` and the `tools/list` description, names the new golden `sync_confluence__fenced`, and lists the two scripts under "Removed".
- `tests/test_write_fence.py` copies the fixture to a temporary directory, calls every registered tool (including `sync_confluence(dry_run=False)` and a forced `reindex`) and the `confluence export` command against a fake Confluence on loopback, and requires that the vault tree not change a single byte outside `90 - Memory/`. A new tool without a call in that test makes it fail.
- Whoever needs to bring Confluence content into the vault runs the export and opens a PR; nothing automates it inside the vault.
- If an unlisted consumer of `dry_run=False` appeared, it receives a visible error with the command that replaces it, never a silent write.
